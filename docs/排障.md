# YUNYIN 排障

> 出现"卡死 / 闪退 / 不出声 / 字是方框"时，照这一页走。
> 架构与规矩见 [架构.md](架构.md)。

## 1. 先把日志打开（只需一次）

在卡里建一个**空文件**：

```text
ux0:/data/yunyin/debug
```

之后应用会把运行日志写进 `ux0:/data/yunyin/yunyin.log`（不建这个文件就一个字都不写，
不影响性能）。想看 HTTP 逐条轨迹再建 `ux0:/data/yunyin/netdbg`。

真机取证顺序：**复现一次 → 立刻退出应用 → 把 `yunyin.log` 整份拿出来**。
Vita3K 的路径是 `ux0/data/yunyin/yunyin.log`（模拟器安装目录下）。

## 2. 日志关键字索引

| 关键字 | 含义 |
| --- | --- |
| `yunyin: start` / `dbg: 音频口已起` | 启动面包屑（卡在哪一步一眼看出） |
| `perf: JS 帧 …ms ← …` | 这一帧慢在哪（后面跟原因，例如"解析清单 xxx.json"） |
| `perf: 600 帧 / 平均 … fps / 慢帧 N 次` | 帧率汇总；"慢帧"是超过 120 ms 的帧 |
| `perf: 切页面 → X` / `perf: Tab 进场/退场` | 页面切换耗时 |
| `HOST: guest 帧耗时 …ms` | 原生调用拖慢了这一帧 |
| `HOST: render 耗时` / `HOST: present 耗时` | 卡在宿主渲染/呈现（GXM / SceGxm） |
| `HOST: guest 帧异常 -> …` | JS 抛异常（含看门狗打断） |
| `remote: 流已打开 size=…` | 在线流建立成功（含 key 与 Cookie 长度） |
| `remote: 预读预算 … KB（整首 … KB 的 1/3，…约 Ns）` | 这一首的预读预算、以及折算成多少秒 |
| `remote: 码率 N kbps（接口 br / 整首大小÷时长 / 未知…）` | Gate 把"剩余字节"换算成"还能播几秒"用的码率，以及它是哪来的 |
| `remote: 缓冲不足，先静音（剩 x / 启动需 15s，码率 N kbps，网络 Z）` | Gate 判定缓冲不够（Z = Fast/Normal/Slow/Starving） |
| `remote: 缓冲恢复（x，网络 Z）` | 恢复播放时的可播秒数 |
| `cache: … 写入 … KB（可命中 / 半截，不入索引）` | 磁盘缓存写入结果 |
| `prefetch: … 已备好` | 下一首预取完成 |
| `yhttp: curl_global_init -> 0` / `yhttp: CA bundle loaded from app0:/certs/…` | 传输层是随包的 libcurl/OpenSSL；这行说明根证书有没有装载（失败：`yhttp: no app CA bundle could be loaded`） |
| `native-font: mode=… provider=vita2d …` | 当前字体后端；正常应为 `mode=pvf`，`mode=disabled` 表示 PVF 没加载上（没有 TTF 回退） |
| `native-font: window text_runs=… text_bytes=… legacy_glyph_ops=…` | 最近一个统计窗口的原生文本提交量；`legacy_glyph_ops` 应为 0 |
| `list: … 已更新` / `listTouched` | 在线清单落盘（界面现在读原生解析视图，不再调 `listTouched`） |
| `login: …` | 登录/会话（含"会话已失效，已退回未登录"） |
| `netdbg#n …` | 只有在卡里建了 `netdbg` 时才有 |

## 3. 崩溃（`psp2dmp`）怎么读

真机崩溃会在 `ux0:/data/` 落一个 `psp2core-….psp2dmp`。看三样：

1. **`Stop reason`**：`0x30004 Data abort` = 访问了非法地址（多半空指针/野指针）；
   `0x30003 Prefetch abort` + `PC: 0x0` = 跳到空地址（函数指针/回调没了）。
2. **`Stack Trace`** 里 `pocketjs-vita.elf+0x偏移` 用符号化脚本反查函数名：

   ```bash
   python3 scripts/symbolize-crash.py dist/pocketjs-vita.elf 0xd14bf 0xcd7c1
   ```

3. **`Fault address`**：`DFAR` 是读/写的坏地址，`IFAR` 是取指令的坏地址。

`dist/pocketjs-vita.elf` 是每次打包都会更新的调试符号副本（不入库）。

## 4. 常见故障对照

| 现象 | 日志里先看 | 常见原因 | 处理 |
| --- | --- | --- | --- |
| 进某个页面直接崩（`PC: 0x0`） | `HOST: guest 帧异常` / dmp 栈 | 回调表/节点被提前释放 | 按 `架构.md §9` 的指针保活规矩查 |
| 一进应用就崩 | `dbg:` 面包屑断在哪一步 | 网络栈初始化顺序（必须先 `yhttp_init`） | 见 §6 第 1 条 |
| **二维码刷新不出来 / 所有在线功能全挂**（歌单一直"同步中"） | `NET error stage=send code=0x80431075`、`NET clock`、`yunyin: 系统时间` | 几乎都是主机日期时间不对（OpenSSL 的证书有效期检查会拒掉所有 HTTPS） | 先把系统时间设对；重启后重跑探针，`NET verdict [range/206 on API host] … PASS` 才算通，见 §6 第 9 条 |
| 在线歌不出声，状态一直"缓冲中" | `remote: 缓冲不足…（网络 Starving）` | 网速真不够；或测速被误判 | 看"网络"分级是否长期 Starving（§6 第 3 条） |
| 播几秒断一下、循环 | `缓冲恢复（10.0s）` → 立刻 `剩 4.9s` | 预读提前量不够 | 已在 1.10 改成滚动预读队列；确认日志里有"预读预算" |
| 在线歌卡死再也不动 | `取数连续失败 N 次` | 网络抖动被当成永久错误 | 现在的策略是自动退避重试，连续失败才判坏 |
| 列表里点歌没反应 | `remote: 解码器打不开这份流` | 地址被拒（403/404）或格式不认识 | 检查是否 VIP/版权；看 `login:` 是否已登录 |
| 词/歌词/列表出现方框或空白 | `native-font: mode=disabled` 或 `legacy_glyph_ops` 非 0 | Vita2D PVF 加载失败，或仍有旧 GLYPH_RUN 产生 | 先确认包内有 `fonts/yunyin.pvf`；再看启动日志和 `legacy_glyph_ops` |
| 切歌/切页面卡一下 | `perf: JS 帧 …`、`HOST: guest 帧耗时` | 帧里干了重活（解析大 JSON / 重建列表 / 每帧 stat） | 把活挪出帧循环（清单已改事件驱动） |
| 待机发热/掉电快 | 帧率汇总 | 画面没变化也在重绘 | 确认 `frame_skip` 生效（`画面没变就跳过 render/present`） |
| 歌单一直"同步中" | `list:` 有没有"已更新" | 未登录 / 网络断 / 接口拒 | 先 `登录 → 刷新`，再看 `login:` 与 `netdbg` |

> `docs/img/online-playlist-1.09.jpg` 仅是历史流式字库故障截图；当前版本不再使用该链路，
> 应以 `native-font:` 启动日志和 `legacy_glyph_ops` 统计为准。

## 5. 构建与测试（改完代码先跑这三条）

WSL2（`pocket-ubuntu`）里，需要 VitaSDK、bun、PocketJS 0.13 检出（`/root/pocketjs013`）：

```bash
# 1) 类型检查（打包器只转译不查类型）
bash scripts/typecheck-app.sh

# 2) 宿主侧测试（加密向量 / JSON / 环形缓存 / 缓冲策略；不需要 Vita）
cd tests && cargo test; cd ..

# 3) 打包
POCKETJS_ROOT=/root/pocketjs013 python3 scripts/build-vpk.py
# → dist/yunyin-main.vpk（同时刷新 dist/pocketjs-vita.elf 调试符号）
```

常用开关（都在 `scripts/yunyin_build/config.py` 里读）：

| 环境变量 | 作用 |
| --- | --- |
| `YUNYIN_FONT=chinese\|japanese` | 随包字体：取 `fonts/<名字>/` 下的字体改名成 `app0:/fonts/yunyin.pvf`（默认 chinese） |
| `YUNYIN_OUT=<名字>` | 产物名 → `dist/<名字>.vpk` |
| `YUNYIN_APP_VER=01.10` | `param.sfo` 里的版本号 |
| `YUNYIN_NO_COVER=1` | 诊断：跳过封面上传（排查封面相关灰屏） |
| `YUNYIN_BARE_GRAPHICS=1` | **已失效**：旧图形补丁在本分支已整组删除，设不设都一样 |
| `YUNYIN_CATCH_HANG=1` | 不要用（只用于判断"死循环还是宿主僵死"） |
| `YUNYIN_NO_FRAME_SKIP=1` | 诊断：保留 PocketJS 原始的每帧 render/present（隔离跳帧逻辑） |
| `YUNYIN_TITLE_ID=<9 位 ID>` | 覆盖 `param.sfo` 里的 TITLE_ID（默认取 `app/core/catalog.ts`） |
| `YUNYIN_CAPTURE_FRAMES=<帧号列表>` | 抓帧调试（在 `pack.py` 里读，产物落 `ux0:data/pocketjs-captures`） |

> 构建镜像里的 **VitaSDK 必须带 OpenSSL 1.1.1**：`native/libs/libcurl_yunyin.a` 是按 1.1.1 的
> API 编的，碰到只有 OpenSSL 1.0.2 的旧 SDK，会在链接阶段报一大片 `undefined reference to
> EVP_MD_CTX_new / OPENSSL_init_ssl / OpenSSL_version_num / BIO_set_shutdown …`。这不是代码
> 问题：换一份带 1.1.1 的 VitaSDK，或用同一份 SDK 重新编 libcurl。

如果 `vita-elf-create` 报 `segment 1 overlaps`，那是 SCE 头需要段 0 末尾留 4 KB，
`build-vpk.py` 会自动换 `YUNYIN_ELF_PAD` 重链，不用手改。

## 6. 踩过的坑（现象 → 根因 → 位置）

1. **真机启动崩溃 `PC=0`**：`yhttp_online()` 在 `sceNetCtlInit` 之前就查状态。
   修法：先 `yhttp_init()` 再初始化网络栈（`native/net/yhttp.c`）。
2. **在线歌"播到 28 秒永久静音"**：Gate 静音时没人去拉数据（死锁）。
   修法：静音路径顺手 `prime()` 叫醒取数线程。
3. **日志永远 `网络 Starving`（假状态）**：用"窗口里剩多少"估速度，而解码器
   同时在消费 → 稳态增量≈0。修法：改用**累计下载字节**（`fetched_total`）。
4. **"播几秒就要缓冲"**：抓满"当前窗 + 一窗预取"后取数线程就闲着，
   解码器跨窗那一下提前量掉到 0。修法：改**滚动预读队列 + 预算**（默认整首 1/3，
   夹在 2–6 MiB），抓满一块立刻接下一块。
5. **切页面/按键卡一下**：后台整首下载抢带宽 + 帧里重建绘制列表。
   修法：按键后 3 秒不预取；柱状动画与清单全文指纹全部删除。
6. **清单刷新每帧 `stat` 六个文件（一次 35~86 ms）**：
   修法：原生写完清单**记名**（`listTouched`）；后来界面干脆不再自己读 JSON，改成读原生
   解析好的有界视图（`netCatalogMenu` / `netCatalogPage` / `netCatalogIds`），旧的那三个
   入口（`listStat` / `listRead` / `listTouched`）只剩实现没人调用。
7. **Vita2D 字体加载失败**：启动日志应有 `native-font: mode=pvf`；失败时会记录
   `mode=disabled`。此时检查 VPK 是否包含 `app0:/fonts/yunyin.pvf`，以及字体文件是否损坏。
8. **0.13 的 devmenu 叠层与 GXM 冲突**：`vita2d_draw_rectangle` 里直接崩
   （`DFAR: 0xff`）。修法：正式包把 devmenu 与 guest 看门狗一起关掉
   （`patch_vita_release_guards`）。
9. **"二维码死活刷新不了"（真机实测：所有 HTTPS 都 0x80431075）**：
    证书校验交给随包编译的 **OpenSSL**，其中**有效期检查是开着的**，主机时钟一旦
    不对，每张证书都算"未生效/已过期"，握手在 `stage=send` 就被拒 —— 探针里连
    `music.163.com/favicon.ico` 都拿不到 206，表现就是"网络明明是好的，二维码刷不出来、
    歌单一个都同步不了"。
    处理：①「设置 → 日期与时间」核对（可开"通过互联网自动设定"）；②重启后重跑探针，
    `NET verdict [range/206 on API host] … PASS` 才算通。
    现在启动日志里有 `yunyin: 系统时间 …`、探针报告里有 `NET clock …` 一行，
    年份明显不对会直接标注出来。
    （旧版这里还要求装 iTLS-Enso 给固件 SceSsl 补 TLS 1.2 —— **现在不需要了**：
    传输走 libcurl/OpenSSL 并强制 TLS 1.2，与固件的 TLS 实现无关。）
10. **Vita3K / dev 宿主上"进去就黑屏"**：看
    `ux0:/data/pocketjs-dev/<TITLEID>/health.json` —— 里面写着
    `"error":"guest JavaScript time budget exceeded"`，就是 **PocketJS dev 宿主
    的"单帧 JS 时间预算"看门狗**把 guest 打断了（真机日志里对应的是
    `HOST: guest 帧耗时 2112ms`：二维码贴图上传 + 探针/同步撞在同一个帧里）。
    处理：①**在 Vita3K 上用正式包**（`PF2A47F97`，我们的构建里这只看门狗是关掉的，
    长帧只会卡一下不会黑屏）；②探针现在启动后先让开 20 秒再跑，避免和首屏同步、
    二维码抢同一套网络栈；③探针的"取消测试"在有别的请求在飞时会自动跳过。
11. **"内置根证书没装上"**：`yhttp: no app CA bundle could be loaded`
    （或探针报告里的 `NET ca        yhttp_load_ca -> 0xFFFFFFFF`）。此时 curl 没有可信根，
    所有 HTTPS 都会失败。检查 VPK 里有没有 `app0:/certs/`（`digicert-global-root-g2.pem` /
    `ca-bundle.pem`）；装载成功会写 `yhttp: CA bundle loaded from app0:/certs/… (N bytes)`。
12. **构建第一步说 PocketJS 补丁"上下文对不上"**（`checkout is neither clean-base nor
    fully patched`）：两个常见原因 ——
    ① `scripts/patches/pocketjs-yunyin.patch` 混进了 CR（在 Windows 上被编辑过一次就会）：
    `git apply` 的每段上下文都带 CR 就全都失配，`file scripts/patches/*.patch` 会写
    "with CRLF line terminators"，把 CR 去掉即可；仓库已用 `.gitattributes` 钉住
    `*.patch text eol=lf`。
    ② PocketJS 检出里还留着**旧版**补丁（`git -C $POCKETJS_ROOT status` 一片 M）：
    补丁既打不上、也反打不掉，在检出里 `git checkout -- .` 复位到干净基线再构建；
    仓库内的 `scripts/patches/pocketjs-yunyin.patch` 才是唯一正规来源。

13. **本地 mp3"偶尔卡一下"（开着 `debug` 时更明显）**：日志每写一行都 `open + write + close`
    一次 `yunyin.log`，C 侧还每次额外 open/close 一遍开关文件 —— 一场上万行日志就是上万次
    SD 操作；音频线程读 mp3 用的是同一张卡（BGM 口缓冲只有 ~21ms），主线程也会被一次
    open/close 拖出 100ms+ 的帧。修法：`platform/log.rs` 改行缓冲（`append` 只写内存，
    主线程每 60 帧 `flush()` 落一次卡），C 侧把开关状态缓存起来。**后来发现这一版仍然卡**：空闲时帧循环能跑 300+ fps，60 帧只有 ~0.17s，等于每秒往卡上写 5~6 次（600 帧汇总里"最慢帧"稳定 40~66ms，就是"每 1~2 秒轻卡一下"）。最终方案见第 20 条。
14. **在线歌"缓冲了一点、3 秒就播完"**：可播秒数 = 剩余字节 ÷ 码率，而码率以前只从
    "整首大小 ÷ 时长"推，缺一个（URL 没长度、清单没时长）就落到 192 kbps 兜底 —— 320 kbps
    被高估 1.7 倍、无损更多；再加上启动判据完全不看实测网速，够阈值就开播，随后必然跌破
    下限。修法：码率优先用接口的 `br`、其次大小÷时长，播放 2 秒后用"已喂字节÷已解码时长"
    实测纠正，并在启动前用 `policy::start_ready()` 问一句"网络是不是在饿死"。

15. **本地歌"起播卡一下"（日志里 1.2~1.4s 的帧）**：本地开流原来是同步的 ——
    `session_end()`（要 join 音频线程）+ `decoder::open()`（fopen/探测/解头）都在 guest
    线程上跑，真机实测一帧能到 1.4s。修法：本地开流也丢后台线程（`yunyin-local-open`），
    和在线路径同一个模式。
16. **PS 键锁会卡半秒到一秒**：`ps_lock::set_locked()` 在主线程直接调
    `sceShellUtilLock/Unlock`，这两个系统调用偶尔要等 shell 事务（日志里紧接着就是
    `HOST: guest 帧耗时 1203ms`）。修法：丢后台线程 + 调用串行化 + "最新请求为准"复核，
    界面不等返回值。
17. **打开歌单会卡一下（~160ms）**：歌单的全量 id（527 首这种）原来在"页ready"的下一帧就
    取，正好压在进场动画上。修法：推迟 30 帧再取（`queueCatalogIds`），点歌时
    `flushCatalogIds()` 立刻补齐，队列导航不会退化成只有当前页 16 首。

18. **翻到歌单后面几页出现"加载中…"**：待取页面原来只有一个槽位，而且只按 `start()`
    取"当前那一页"。一屏 6 行会**跨页**（`start=13` 显示第 13~18 行，其中 16~18 行属于
    `offset=16` 那一页），该页从来没被请求过 —— 那几行只有 id、没有元数据，于是显示占位
    "加载中…"（日志特征：`page_offset` 一直 0、`list_page_begin` 也只有 `offset=0`）。
    修法：待取页改成小队列（去重、最多 4 条，每帧处理一条），并把 `queueCatalogWindow()`
    同时排上"start 所在页"和"窗口最后一行所在页"。

19. **界面"卡卡的"（本地播放时尤其明显）**：有些清单**根本同步不下来**（原生取数失败、文件没
    落盘），而 `page_json` 对这种情况永远回 `loading`。界面原来每 3 帧重试一次 —— 真机日志里
    同一个文件被请求了 **1.2 万次**（`list_page_begin trace=…` 一路涨到 12532），主线程从不
    空闲，播放时就表现为持续卡顿。修法：`loadCatalogPage` 对 loading 走指数退避
    （3/6/12/24/48… 帧，192 帧封顶），`queueCatalogPage` 加次数上限（8 次后放弃；清单版本
    变化、或用户重新点开该歌单时重置）。

20. **本地播放"每 1~2 秒轻卡一下"**：上一版把日志落卡放在帧循环里（每 60 帧），而空闲时帧循环
    跑 300+ fps —— 60 帧只有 0.17 秒，等于每秒向 SD 写 5~6 次、每次几十 ms；600 帧汇总里
    "最慢帧"几乎每个窗口都是 40~66ms，正好对上"1 帧轻卡一下"的体感（音频线程读 mp3 也用
    同一张卡，所以听起来也像断了一下）。修法：`platform/log.rs` 起一个后台线程
    `yunyin-log`，按**时间**每 3 秒把缓冲落一次卡（先把缓冲换出来再写，不占 `LOG_BUF` 锁），
    主线程与音频线程都不再碰 SD 写；落卡超过 5ms 会记一行 `log: 落卡 N 字节耗时 Mms`。

21. **CPU 吃满（"3 个核 80%、第 4 个看戏"）**：Vita 的第 4 个核 CPU3 是系统保留的，应用默认
    用不了（要用得装内核插件 CoreUnlocker 那类），所以"3 核 80%"= 能用的 3 个核已经被吃满，
    问题不是核数不够而是**白烧**：宿主主循环"能跑多快跑多快"（只在画面变了才 present），
    空闲时真机实测 300~380 fps —— 每秒 350 次 JS tick + DrawList 构建 ≈ 一个核。修法：
    `ui/frame_skip.rs` 给整条主循环**限帧 16ms（≈60fps）**，睡掉多余时间；音频不受影响
    （音频是 `yunyin-bgm` 原生线程喂口，`audioEngine.pump()` 在该版本是空实现），画面一变
    照常全速，按键延迟最多多一帧。

22. **想用第 4 个核（CPU3 / 社区叫 CPU4）**：VitaSDK `psp2/kernel/cpu.h` 里核是按高位区分的
    —— `USER_0/1/2 = 0x10000/0x20000/0x40000`、`SYSTEM = 0x80000`（系统保留核）、
    `USER_ALL = 0x70000`。应用默认只拿到 USER_ALL 那三个核，所以 CPU 监视器上是
    "3 个核忙、第 4 个看戏"。**注意别写成 0x8**：那是不存在的核位，内核会直接拒。
    要用第 4 个核需要两半：
      * 内核侧：装 CapUnlocker / CoreUnlocker 这类 `.skprx`（放 `ur0:tai/`，在
        `config.txt` 的 `*KERNEL` 段加载，开机生效）。用户态程序**没有权限**加载内核
        模块，应用自己做不到。
      * 应用侧：把 `0x80000` 并进线程掩码（`platform/cpu.rs::widen`，音频线程与主循环
        各调一次），装好插件后线程才会真的被调度过去。日志会打
        `cpu: <线程> 亲和性 0x70000 -> 0xF0000 ret=0`；`ret` 为负说明内核拒绝（没插件）。

23. **界面"进去直接黑屏"**：运行期**没有 `setTimeout` / `setInterval`** —— 用了就抛
    `ReferenceError: setInterval is not defined`，组件一挂载就炸，整屏黑。真机 PocketJS 会把
    它写进 `ux0:data/pocketjs-dev/<TITLEID>/health.json`（`"error":"ReferenceError: …"`），
    黑屏时**先看这个文件**，比翻 yunyin.log 快。所有"定期刷新"都要由帧循环按帧数驱动
    （`frameCounter % N === 0`），例如状态栏的 `pollHostInfo()`。

## 7. 提交/发布纪律

* 每轮改动：`typecheck-app.sh` + `tests/` + `build-vpk.py` 三条全绿再发。
* VPK 不进版本库（`.gitignore` 里排除），走 GitHub Releases。
* 版本号只改一处：`scripts/yunyin_build/config.py` 的 `APP_VER`（默认 `01.10`）。构建第一步的
  `check_versions()` 会校验 `app/pocket.json` 的 `version`（PocketJS 要求严格 `X.Y.Z`，
  所以写 `01.10` 对应的 `1.10.0`）、`app/core/theme.ts` 的两个常量、`native/rs/mod.rs`
  启动日志里的版本都与它一致，漏改任何一处直接构建失败。
