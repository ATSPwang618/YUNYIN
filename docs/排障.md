# YUNYIN 排障

> 出现"卡死 / 闪退 / 不出声 / 字是方框"时，照这一页走。
> 架构与规矩见 [架构.md](架构.md)。

## 1. 先把日志打开（只需一次）

在卡里建一个**空文件**：

```text
ux0:/data/yunyin/debug
```

之后应用会把运行日志写进 `ux0:/data/yunyin/yunyin.log`（不建这个文件就一个字都不写，
不影响性能）。想看 HTTP 逐条轨迹再建 `ux0:/data/yunyin/netdbg`。

真机取证顺序：**复现一次 → 立刻退出应用 → 把 `yunyin.log` 整份拿出来**。
Vita3K 的路径是 `ux0/data/yunyin/yunyin.log`（模拟器安装目录下）。

## 2. 日志关键字索引

| 关键字 | 含义 |
| --- | --- |
| `yunyin: start` / `dbg: 音频口已起` | 启动面包屑（卡在哪一步一眼看出） |
| `perf: JS 帧 …ms ← …` | 这一帧慢在哪（后面跟原因，例如"解析清单 xxx.json"） |
| `perf: 600 帧 / 平均 … fps / 慢帧 N 次` | 帧率汇总；"慢帧"是超过 120 ms 的帧 |
| `perf: 切页面 → X` / `perf: Tab 进场/退场` | 页面切换耗时 |
| `HOST: guest 帧耗时 …ms` | 原生调用拖慢了这一帧 |
| `HOST: render 耗时` / `HOST: present 耗时` | 卡在宿主渲染/呈现（GXM / SceGxm） |
| `HOST: guest 帧异常 -> …` | JS 抛异常（含看门狗打断） |
| `remote: 流已打开 size=…` | 在线流建立成功（含 key 与 Cookie 长度） |
| `remote: 预读预算 …（整首 … 的 1/3）` | 这一首的预读预算算出来是多少 |
| `remote: 缓冲不足，先静音（剩 x / 启动需 y，网络 Z）` | Gate 判定缓冲不够（Z = Fast/Normal/Starving） |
| `remote: 缓冲恢复（x，网络 Z）` | 恢复播放时的可播秒数 |
| `cache: … 写入 … KB（可命中/半截）` | 磁盘缓存写入结果 |
| `prefetch: … 已备好` | 下一首预取完成 |
| `cjk: mode=… status=… host={…} js={…}` | 字库现场：`resident/inked/unsupported/rejected` 是宿主侧，`loaded/err` 是 JS 侧 |
| `list: … 已更新` / `listTouched` | 在线清单落盘 |
| `login: …` | 登录/会话（含"会话已失效，已退回未登录"） |
| `netdbg#n …` | 只有在卡里建了 `netdbg` 时才有 |

## 3. 崩溃（`psp2dmp`）怎么读

真机崩溃会在 `ux0:/data/` 落一个 `psp2core-….psp2dmp`。看三样：

1. **`Stop reason`**：`0x30004 Data abort` = 访问了非法地址（多半空指针/野指针）；
   `0x30003 Prefetch abort` + `PC: 0x0` = 跳到空地址（函数指针/回调没了）。
2. **`Stack Trace`** 里 `pocketjs-vita.elf+0x偏移` 用符号化脚本反查函数名：

   ```bash
   python3 scripts/symbolize-crash.py dist/pocketjs-vita.elf 0xd14bf 0xcd7c1
   ```

3. **`Fault address`**：`DFAR` 是读/写的坏地址，`IFAR` 是取指令的坏地址。

`dist/pocketjs-vita.elf` 是每次打包都会更新的调试符号副本（不入库）。

## 4. 常见故障对照

| 现象 | 日志里先看 | 常见原因 | 处理 |
| --- | --- | --- | --- |
| 进某个页面直接崩（`PC: 0x0`） | `HOST: guest 帧异常` / dmp 栈 | 回调表/节点被提前释放 | 按 `架构.md §9` 的指针保活规矩查 |
| 一进应用就崩 | `dbg:` 面包屑断在哪一步 | 网络栈初始化顺序（必须先 `yhttp_init`） | 见 §6 第 1 条 |
| 在线歌不出声，状态一直"缓冲中" | `remote: 缓冲不足…（网络 Starving）` | 网速真不够；或测速被误判 | 看"网络"分级是否长期 Starving（§6 第 3 条） |
| 播几秒断一下、循环 | `缓冲恢复（10.0s）` → 立刻 `剩 4.9s` | 预读提前量不够 | 已在 1.10 改成滚动预读队列；确认日志里有"预读预算" |
| 在线歌卡死再也不动 | `取数连续失败 N 次` | 网络抖动被当成永久错误 | 现在的策略是自动退避重试，连续失败才判坏 |
| 列表里点歌没反应 | `remote: 解码器打不开这份流` | 地址被拒（403/404）或格式不认识 | 检查是否 VIP/版权；看 `login:` 是否已登录 |
| 词/歌词/列表出现方框或空白 | `cjk: …host={…unsupported:N} js={…loaded:N err:…}` | ①字库没加载进来（`loaded:0`+`err`）②字符集确实没这个字（`unsupported` 涨） | ①见 §6 第 7 条 ②把缺的字发出来补字符集 |
| 切歌/切页面卡一下 | `perf: JS 帧 …`、`HOST: guest 帧耗时` | 帧里干了重活（解析大 JSON / 重建列表 / 每帧 stat） | 把活挪出帧循环（清单已改事件驱动） |
| 待机发热/掉电快 | 帧率汇总 | 画面没变化也在重绘 | 确认 `frame_skip` 生效（`画面没变就跳过 render/present`） |
| 歌单一直"同步中" | `list:` 有没有"已更新" | 未登录 / 网络断 / 接口拒 | 先 `登录 → 刷新`，再看 `login:` 与 `netdbg` |

## 5. 构建与测试（改完代码先跑这三条）

WSL2（`pocket-ubuntu`）里，需要 VitaSDK、bun、PocketJS 0.13 检出（`/root/pocketjs013`）：

```bash
# 1) 类型检查（打包器只转译不查类型）
bash scripts/typecheck-app.sh

# 2) 宿主侧测试（加密向量 / JSON / 环形缓存 / 缓冲策略；不需要 Vita）
cd tests && cargo test; cd ..

# 3) 打包
POCKETJS_ROOT=/root/pocketjs013 YUNYIN_BARE_GRAPHICS=1 python3 scripts/build-vpk.py
# → dist/yunyin-main.vpk（同时刷新 dist/pocketjs-vita.elf 调试符号）
```

常用开关（都在 `scripts/yunyin_build/config.py` 里读）：

| 环境变量 | 作用 |
| --- | --- |
| `YUNYIN_FONT=chinese\|japanese` | 用哪套字体（日文版用 `fonts/japanese/MSMINCHO.TTF`） |
| `YUNYIN_THEME=light\|dark\|pure\|anime` | 烘焙时优先的皮肤 |
| `YUNYIN_OUT=<名字>` | 产物名 → `dist/<名字>.vpk` |
| `YUNYIN_APP_VER=01.10` | `param.sfo` 里的版本号 |
| `YUNYIN_FORCE_CJK_BAKED=1` | 诊断：强制走内置字库（排查流式字库相关黑屏） |
| `YUNYIN_NO_COVER=1` | 诊断：跳过封面上传（排查封面相关灰屏） |
| `YUNYIN_BARE_GRAPHICS=1` | **正式包必带**：跳过与 0.13 渲染模型冲突的图形补丁 |
| `YUNYIN_CATCH_HANG=1` | 不要用（只用于判断"死循环还是宿主僵死"） |

如果 `vita-elf-create` 报 `segment 1 overlaps`，那是 SCE 头需要段 0 末尾留 4 KB，
`build-vpk.py` 会自动换 `YUNYIN_ELF_PAD` 重链，不用手改。

## 6. 踩过的坑（现象 → 根因 → 位置）

1. **真机启动崩溃 `PC=0`**：`yhttp_online()` 在 `sceNetCtlInit` 之前就查状态。
   修法：先 `yhttp_init()` 再初始化网络栈（`native/net/yhttp.c`）。
2. **在线歌"播到 28 秒永久静音"**：Gate 静音时没人去拉数据（死锁）。
   修法：静音路径顺手 `prime()` 叫醒取数线程。
3. **日志永远 `网络 Starving`（假状态）**：用"窗口里剩多少"估速度，而解码器
   同时在消费 → 稳态增量≈0。修法：改用**累计下载字节**（`fetched_total`）。
4. **"播几秒就要缓冲"**：抓满"当前窗 + 一窗预取"后取数线程就闲着，
   解码器跨窗那一下提前量掉到 0。修法：改**滚动预读队列 + 预算**（默认整首 1/3，
   夹在 2–6 MiB），抓满一块立刻接下一块。
5. **切页面/按键卡一下**：后台整首下载抢带宽 + 帧里重建绘制列表。
   修法：按键后 3 秒不预取；柱状动画与清单全文指纹全部删除。
6. **清单刷新每帧 `stat` 六个文件（一次 35~86 ms）**：
   修法：原生写完清单**记名**（`listTouched`），界面只读变过的文件，15 秒慢扫兜底。
7. **流式字库"全是空白"**：`offload_local` 的每帧闸门（`SENT`/`TAKEN`）没人复位
   —— PSP 宿主在帧循环里调 `offload_local::frame()`，Vita 宿主漏了，于是第一条
   请求成功、之后每条都发不出去（日志：`loaded:0, err:Error: Provider unavailable`）。
   修法：`scripts/yunyin_build/patches_host.py` 在 `call_frame` 开头补这一行。
8. **字库容量被拒 → 整个流式字库进 error**：预留字形条数写死 384 时，
   一屏列表的文字量就够把它挤爆。修法：容量阶梯 `[1024, 768, 512, 384]`，
   被拒自动退档；字符集也从 GB2312 扩到 29,894 字（读字体 cmap 生成）。
9. **0.13 的 devmenu 叠层与 GXM 冲突**：`vita2d_draw_rectangle` 里直接崩
   （`DFAR: 0xff`）。修法：正式包把 devmenu 与 guest 看门狗一起关掉
   （`patch_vita_release_guards`）。

## 7. 提交/发布纪律

* 每轮改动：`typecheck-app.sh` + `tests/` + `build-vpk.py` 三条全绿再发。
* VPK 不进版本库（`.gitignore` 里排除），走 GitHub Releases。
* 版本号在 `scripts/yunyin_build/config.py` 的 `APP_VER`；改完记得同时在
  `app/pocket.json` 里同步 `version`。
