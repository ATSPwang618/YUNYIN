# YUNYIN 架构

> 读者：要改这个项目的人（包括三个月后的自己）。
> 目标：一眼看清"东西在哪、数据怎么流、哪些规矩不能破"。
> 排障/构建命令见 [排障.md](排障.md)。

## 0. 一张图

```text
        ┌────────────────────────────── app/ （SolidJS 界面 · PocketJS 0.13 宿主） ──────────────────────────────┐
        │            main.tsx（框架入口）→ app.tsx（帧循环 + 状态机）  core/*  pages/*  components/*             │
        └──────────────────────────────────────────┬─────────────────────────────────────────────────────────────┘
                                globalThis.vitaMedia（QuickJS FFI 桥）
        ┌──────────────────────────────────────────┴─── native/（Rust + C） ─────────────────────────────────────┐
        │         bridge.rs（FFI 表） catalog.rs qr.rs tags.rs decoder.rs   bgm.rs（音频线程 + BGM 口）          │
        │         provider/netease/*（登录/歌单/榜单/URL 解析）   source/*（取数 + 缓冲策略 + 磁盘缓存）         │
        │               ui/native_text.rs（TEXT_RUN → Vita2D PVF）      net/*（HTTP 传输 + 探针）                │
        └──────┬──────────────────────────────────────┬──────────────────────────────────────────┬───────────────┘
               │                                      │                                          │
net/yhttp.c（libcurl/OpenSSL，Range + 中止）
                                ux0:/data/yunyin/cache.dat（32 MB 环形缓存）
                                                                                   audio/yplayer.c（六格式解码）
```

数据只有两条来路：**卡里的本地曲库**（`ux0:/data/yunyin/music/`）和
**网易云在线**（清单 JSON + 加密接口 + Range 流）。界面只认"统一的曲目结构"，
不关心这首歌从哪来。

## 1. 目录 / 模块地图

| 路径 | 干什么 | 关键文件 |
| --- | --- | --- |
| `app/` | 界面层（PocketJS 应用目录，**目录名/结构由框架约定**） | `main.tsx`（框架入口，只 import 组件根）、`app.tsx`（状态机）、`pocket.json`、`colors.json` |
| `app/core/` | 与界面无关的"能力"：音频口、曲库、主题、原生文本适配、在线清单视图、性能计时 | `audio.ts` `library.ts` `media.ts` `catalog.ts` `qr.ts` `theme.ts` `perf.ts` `motion.ts` `util.ts` `types.ts` |
| `app/pages/` | 右侧四个页签 + 子页 | `tracks.tsx` `albums.tsx` `menu.tsx` `settings.tsx` `lyrics.tsx` `account.tsx` `about.tsx` `keys.tsx` |
| `app/components/` | 可复用控件 | `player.tsx`（左侧播放器卡片）`rows.tsx` `tabbar.tsx` `subpage.tsx` `focus_indicator.tsx` |
| `native/rs/` | 原生层主体（Rust）。构建时整体暂存成宿主 crate 的 `media` 模块 | `mod.rs` `bridge.rs` `bgm.rs` `catalog.rs` `qr.rs` `tags.rs` `decoder.rs` + `platform/` `net/` `provider/` `source/` `ui/` |
| `native/audio/` | **解码**（C）：mpg123 / libvorbis / opusfile / dr_wav / dr_flac + m4a/AAC 硬解 | `yplayer.c`、`ym4a.c`、`yaac.c`、`yp_io_file.c`、`yunyin_log.h` |
| `native/net/` | 网络（C，薄 ABI + libcurl/OpenSSL，Range 流） | `yhttp.c` `yhttp.h` `openssl_compat.c` |
| `native/host/` | 宿主侧小工具（C） | `yunyin_image.c`（封面解码）`yunyin_listdir.c`（目录扫描）`yunyin_log.h` |
| `native/vendor/`、`native/libs/` | 第三方头文件与预编译静态库（8 个 `.a`） | `dr_wav.h` `dr_flac.h` `stb_image.h` `opus/`、`libvita2d.a` 等 |
| `asset/` | 主题素材（构建时复制成 app 内的 `asset/`） | `asset/ui/<主题>/*.png`（5 套主题，每套 16 张控制图标） |
| `fonts/` | 字体**源文件**（不是成品 PVF） | `chinese/SourceHanSansSC-Bold.otf`（思源黑体 SC Bold）、`japanese/MSMINCHO.TTF` |
| `scripts/` | 构建与检查 | `build-vpk.py`（唯一打包入口）、`yunyin_build/`（实现）、`patches/`（PocketJS 补丁）、`typecheck-app.sh` |
| `scripts/tools/` | 素材/曲库维护工具（不参与构建） | `gen-flat-themes.py` `gen-theme-icons.py` `tagcheck.py` |
| `tests/` | 宿主侧测试（cargo，不需要 Vita）。目录名沿用的是"暂存后的 crate 模块名" | `tests/src/media/…` 对应源码 `native/rs/…`；`cargo test` → 加密向量 / JSON / 环形缓存 / 缓冲策略 |

> 下文出现的 `source/http.rs`、`provider/netease/…`、`ui/native_text.rs` 这类简写，都是
> `native/rs/` 下的同名文件。构建时 `native/rs` 会被整体暂存成宿主 crate 的 `media` 模块，
> 所以 Rust 源码里写的是 `crate::media::source::…`；`tests/src/media/` 也是同一个命名的来源。

构建派生物（不入库，构建时自动生成）：
`app/theme-seed.tsx`（由 `colors.json` 生成）、`app/images.json`（扫 `asset/**` 生成）。
字体：`fonts/chinese/SourceHanSansSC-Bold.otf` 在打包时**只改文件名**复制成
`app0:/fonts/yunyin.pvf`（`PVF` 只是 libvita2d 的加载入口名，文件本身仍是 OpenType，由 ScePvf 解析）。
这一处源路径在 `pack.py` 里写死 `chinese`：`YUNYIN_FONT=japanese` 只影响构建期烘焙输入，
**不会**换掉随包字体。

## 2. 界面层（app/）

* **框架入口是 `app/main.tsx`**（`pocket.json` 里的 `entry`，它只 import 组件根）；
  **`app/app.tsx` 是唯一的状态机**，故意保持单文件（官方 Playground 预览要求同构）。
  它负责：帧循环、页签/子页切换、列表虚拟化、按键路由、状态词。
* **`core/` 里都是"能力"**，不认识界面：`audio.ts` 是对原生的薄封装，
  `library.ts` 管曲库扫描与收藏，`catalog.ts` 读原生解析好的在线清单视图，
  `qr.ts` 把原生编好的二维码位图交给界面，`theme.ts` 管 5 套配色
  （`colors.json` 是数据源，浅蓝/浅绿/浅紫由 `scripts/tools/gen-flat-themes.py` 从浅色派生），
  `perf.ts` 记账（`perf: JS 帧 …`）。文字直接用框架的 `<Text>`，中间没有适配层。
* **`pages/` 只画自己那一页**，`components/` 只画控件；两者都不直接碰原生，
  一律通过 `app.tsx` 传下来的访问器。
* 列表是**虚拟列表**：屏幕上只有 8~15 个 Item 节点，滚动复用；清单里的歌曲
  按需物化（只对可见窗口 + 邻窗解析），不做整表。

## 3. 原生层（native/rs/）

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| `bridge.rs` | JS ↔ Rust 的 FFI 表（`globalThis.vitaMedia`） | 所有同步入口都在这里，参数校验也在这里 |
| `bgm.rs` | 播放会话、音频线程、BGM 口、息屏续播 | 播放句柄只在音频线程换，换之前先 `join` |
| `catalog.rs` | 原生解析 `list/` 里的在线清单 JSON | 只把有界的菜单 / 页 / 榜单 ID 视图交给界面，不把整份 JSON 推给 JS；解析结果存 `Arc<Document>`，取页只复制一个计数（早期每次深拷贝整份文档，一页 30~200ms） |
| `qr.rs` | 原生二维码编码（128×128 RGBA） | 登录页只拿到位图 |
| `tags.rs` | 标签、内嵌封面、内嵌歌词 | 只读文件头 1 MB + 64 KB 元数据前缀 |
| `decoder.rs` | `native/audio/yplayer.c` 的 FFI | 拉模式：JS 侧只看到"要 PCM" |
| `provider/netease/` | 登录（二维码）/ 歌单 / 榜单 / 每日推荐 / URL 解析 | `crypto.rs` 是 weapi/eapi 加密；`quality` 决定音质档 |
| `source/` | 在线播放的取数、缓存、缓冲策略 | 见下一节 |
| `net/` | HTTP 传输词汇 + `yhttp.c` 的 FFI + 探针 | Rust 侧窗口与 C 侧 `YHTTP_WINDOW` 严格同尺寸（1 MiB） |
| `platform/` | 卡里的路径、日志、store（键值文件）、时钟、电源、PS 键锁 | 日志/探针受卡里的开关文件控制 |
| `ui/` | Vita2D 原生文字（`native_text.rs`）与跳帧（`frame_skip.rs`） | 见 §6 |

## 4. 在线播放链路（最要紧的一节）

```text
   resolve（加密接口拿 URL）
        ↓
   net/yhttp.c          一个 Range 请求 = 1 MiB（YHTTP_WINDOW）
        ↓
   source/http.rs       HttpRangeSource：**滚动预读队列**
                        · 块 1 MiB（与 C 侧窗口同尺寸）
                        · 预算 = 整首的 1/3，夹在 2–6 MiB（policy::readahead_budget）
                        · 取数线程抓满一块立刻抓下一块（不再"抓完就睡"）
                        · 升格换下来的块留两块复用（稳态零 malloc）
        ↓
   source/remote.rs     秒级 Gate（policy::GateState，纯逻辑、宿主可测）
        ↓
   audio/yplayer.c      解码 → PCM → BGM 口
```

**缓冲阈值（`source/policy.rs`，单位是"秒"不是 KB）**：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `START_BUFFER_MS` | 15 s | 首次启动要凑够才出声（文件头/封面也占字节，留出误差） |
| `MIN_BUFFER_MS` | 7 s | 播放中掉到它以下才 rebuffer（迟滞） |
| `RESUME_BUFFER_MS` | 12 s | rebuffer 后回到它才继续 |
| `TARGET_BUFFER_MS` | 20 s | 网络好时希望维持的量（预取让路判据） |
| `PREFETCH_MIN_BUFFER_MS` | 40 s | 下一首真正开跑要求的缓冲 |
| `PREFETCH_QUIET_MS` | 3 s | 用户刚按过键这段时间内**不预取**（保按键响应） |

**码率**（把字节换算成"秒"的唯一输入）按这个顺序取：接口给的 `br` → "整首大小 ÷ 时长"
→ 兜底 192 kbps；播放开始约 2 秒后还会用**已喂给解码器的字节 ÷ 已解码时长**实测纠正
（`remote::effective_bitrate` 取声明值与实测值的**较大者** —— 宁可少算可播秒数，也不要再出现
"显示够 15 秒、其实 3 秒就没声了"）。`policy::start_ready()` 在"够 START 秒"之外再加一道：
网速明显跑不过码率（Starving）时先不出声，只等预读队列抓满或缓冲超过 TARGET。

**磁盘缓存（`source/diskcache.rs`）**：固定 32 MB 的 `cache.dat` + `cache.idx`，
环形覆盖、正常播放期间**不删文件**（SD2Vita 上最贵的是 create/write/close/remove）。
整首写满才登记进索引；正在播的那首被保护，写入会让开。

**TLS 与根证书**：传输层**不是** SceHttp/SceSsl，而是随 VitaSDK 用的 **libcurl + OpenSSL**
（`native/net/yhttp.c` 只保留一层薄 C ABI）。证书校验由 OpenSSL 做：默认打开
`CURLOPT_SSL_VERIFYPEER` / `CURLOPT_SSL_VERIFYHOST`（只有显式要求"不校验"的探针对照测试才关），
并用 `CURLOPT_SSLVERSION` 强制 **TLS 1.2**（这份 VitaSDK 的 libcurl 没编进 TLS 1.3）。

信任库也不再看固件那一份：`certs/` 随包发布（**DigiCert Global Root G2**，网易云 API 与
`*.music.126.net` CDN 整条链都用它，另附 `ca-bundle.pem` 兜底），`yhttp_init()` 调
`yhttp_load_ca()` 把 PEM 读进内存，优先用 `CURLOPT_CAINFO_BLOB` 交给 curl，
不支持时退回 `CURLOPT_CAINFO` + `app0:/` 路径。于是：

* 证书**有效期**照样会校验 —— 机器系统时间不对，握手依旧失败（`0x80431075`），与旧实现相同；
* 但"老固件 SceSsl 只到 TLS 1.1"不再是问题，**不需要再装 iTLS-Enso**；
* 加载失败只记 `yhttp: no app CA bundle could be loaded`（启动时会先 `yhttp_load_ca()`），
  不会回退到固件根库。

**下一首预取（`source/prefetch.rs`）**：只在"当前曲已全部到手"或
"缓冲 ≥ 40 s 且网络 FAST 且用户 3 秒没按键"时跑；单曲 > 16 MiB 不预取。

## 5. 在线清单：JSON 落盘 → 原生解析视图

原生每次启动在后台把清单写成 JSON（`ux0:/data/yunyin/list/`），**断网也能看上次的内容**
（界面读的是原生解析好的视图，不是自己解析文件）：

| 文件 | 内容 | 来源 |
| --- | --- | --- |
| `discover.json` | 发现页：热门推荐歌单列表 | `/personalized` |
| `daily.json` | 每日推荐（需登录） | `/recommend/songs`（加密 weapi v3） |
| `account_playlists.json` | 我的歌单（需登录） | `/user/playlist` |
| `toplist_<榜单id>.json` | 四个榜单各一个文件 | `/playlist/detail` |
| `playlist_<歌单id>.json` | 打开过的歌单/榜单快照 | `/playlist/detail` |

原生写入用 **tmp + rename 原子替换**（掉电/强杀不会留半截 JSON）；解析也留在原生侧，
**解析成有界视图**（`catalog.rs`）：界面通过 `netCatalogVersion` / `netCatalogMenu` /
`netCatalogPage` / `netCatalogIds` 只取当前要显示的那一段，**不再自己读 JSON**，
所以"每帧 stat 六个文件"的问题从根上消失了。全量 id（几百上千条那种）推迟到进场动画
之后再取，点歌时立刻补齐，不和首屏抢帧。

（旧版那一套 `listTouched` / `listStat` / `listRead` 在原生侧仍然存在并注册着，
但界面已经不再调用，`app/core/types.ts` 里还留着它们的类型声明。）

## 6. 字体渲染

运行期只有**一条**文字路径：

* PocketJS core 把普通文本打成 `TEXT_RUN`；Vita 宿主 `native/rs/ui/native_text.rs` 通过
  `set_text_measure` 装上度量/绘制回调，用 `vita2d_load_custom_pvf` 打开两份 ScePvf face
  （12px / 16px 两个槽位，`vita2d_pvf_set_char_size` 决定栅格尺寸），按需栅格化后直接绘制。
* `app0:/fonts/yunyin.pvf` 就是 `fonts/chinese/SourceHanSansSC-Bold.otf` 改名而来
  （OpenType，由 ScePvf 解析，详见 §8），所以"PVF"只是加载入口的名字，不是另一种字体格式。
* 加载失败只记 `native-font: mode=disabled`，**没有 TTF 回退**，不会再悄悄启用第二套渲染实现。
* 宿主补丁把旧的图集上传（`register_font_atlas`）和 `GLYPH_RUN` 绘制分支摘掉：
  前者永不上传 GPU 纹理，后者的每次进入只被计数（`legacy_glyph_ops`）。
* 计数都在 `native-font:` 日志里：
  `native-font: window text_runs=… text_bytes=… legacy_glyph_ops=… atlas12_glyphs=… atlas12_failures=… atlas16_glyphs=… atlas16_failures=…`
  （`legacy_glyph_ops` 应恒为 0；启动行里的 `legacy_glyph=0` 是字面量，不是实测值。）

**仍然存在、但宿主已不消费的遗留**（改字体相关代码前要知道）：

* PocketJS 的字体归档仍在构建期烘焙（`bun tools/build.ts --density=2 --font-regular/bold=…`），
  `app/pocket.json` 也仍声明 `text.glyphs.baked` / `text.glyphs.streamed`，core 侧的
  `font_stream` 页队列也还在被本仓库的补丁维护；只是这份归档不再被上传或绘制。
* 它不再收割曲库字符（没有 `--extra-chars`）：图集内容只由源码字面量决定，
  界面缺字只取决于随包字体里有没有那个字形。

## 7. 线程与性能纪律

| 规则 | 为什么 |
| --- | --- |
| 网络/磁盘 I/O 只在取数线程里做，**音频线程绝不等 I/O** | SD2Vita 抖动不能变成断音 |
| 开流与系统调用（本地 open、PS 键锁、在线解析）一律放后台线程 | 真机实测同步做会让所在帧卡 0.3–1.4s（日志里对应 `perf: 起播` / `ps lock` 后的长帧） |
| 日志只在内存里攒，**后台线程每 3 秒落一次卡**（`platform/log.rs`） | 每行一次 open/write/close 在 SD2Vita 上是几十 ms；帧循环里落卡会让 300fps 的空闲循环每秒写卡 5~6 次（实测最慢帧 40~66ms） |
| 主循环限帧 16ms（≈60fps，`ui/frame_skip.rs`） | 宿主循环不设上限时空闲跑到 300~380 fps，等于白烧一个核（Vita 只有 3 个可用核，CPU3 系统保留） |
| 帧循环里不做重活（解析大 JSON、重建绘制列表、每帧 stat 文件） | 真机上这些都是"卡一下"的来源 |
| 状态栏信息走原生桥接 `hostInfo`（电量/时间/联网），帧循环每 300 帧刷一次（`platform/hostinfo.rs`） | 运行期没有 `setTimeout/setInterval`，用定时器会直接黑屏（PocketJS health.json 里抓到过） |
| 想用第 4 个核：`platform/cpu.rs` 把 `SCE_KERNEL_CPU_MASK_SYSTEM`(0x80000) 并进线程掩码 | 应用默认只有 `USER_ALL`(0x70000)；没装 CapUnlocker 时内核回 `0x80028025`（日志里有判据） |
| 画面没变化就跳过 render/present（`frame_skip`） | 暂停/待机时省电、省发热 |
| 持续动画用**编译期烘好的 keyframe**（`animate-pulse` 等），一次性动画用 `animate()` | 稳态零 JS；官方只把 bake 用于固定循环 |
| 用户按键后 3 秒内不做后台预取 | 按键响应优先于"先把下一首下好" |

## 8. 构建流水线（`scripts/build-vpk.py`）

```text
apply_pocketjs_patch()   把仓库内固定的 PocketJS 源码补丁打到干净检出
                         （scripts/patches/pocketjs-yunyin.patch）
pack.stage()             app/ + asset/ + native/ 暂存进 PocketJS 检出
                         （apps/yunyin、hosts/vita；native/rs → hosts/vita/src/media）
apply_host_patches()     把官方宿主打成 YUNYIN 宿主（媒体模块、帧循环、正式包开关、
                         诊断、Vita2D 原生文字）
pack.build_vpk()         bun tools/build.ts（编译 + PJFA 字体烘焙）
                         + bun tools/vita.ts（Rust/C 构建，libvita2d.a 随 native/ 进树）
pack.repack()            换 TITLE_ID / 权限 eboot / 中文标题，附 fonts/yunyin.pvf 与 certs/，
                         重打 VPK → dist/<YUNYIN_OUT>.vpk
```

配置全部集中在 `scripts/yunyin_build/config.py`：`POCKETJS_ROOT`（默认 `/root/pocketjs`，正式构建指 0.13 检出）、
`VITASDK`、`YUNYIN_OUT`、`YUNYIN_APP_VER`（默认 `01.10`）、`YUNYIN_FONT`，诊断开关
`YUNYIN_NO_COVER` / `YUNYIN_CATCH_HANG` / `YUNYIN_NO_FRAME_SKIP` / `YUNYIN_TITLE_ID`，
另有 `YUNYIN_CAPTURE_FRAMES`（在 `pack.py` 里读，用于抓帧调试）。版本号只有 `APP_VER` 一处来源，
构建第一步的 `check_versions()` 会校验 `pocket.json` / `theme.ts` / 原生启动日志与它一致。

两个历史包袱：

* **旧的 `YUNYIN_BARE_GRAPHICS` 开关已经删掉**：本分支把两组图形补丁整组移除（`patches_graphics.py`
  一并删除），宿主补丁无条件执行，这个开关不再有任何消费者。
* **`scripts/patches/libvita2d-pvf-*.patch` 不在构建流程里应用**：`native/libs/libvita2d.a` 是预编译静态库，
  这两个补丁是当初离线改 libvita2d 源码、重编 `.a` 的手工记录（新增 `vita2d_pvf_set_char_size` /
  `vita2d_pvf_get_glyph_stats`、把图集从 512 提到 2048）。换这份 `.a` 时 `pack.stage()` 会先
  检查这两个符号在不在，缺了立刻报错（以前是一路链到失败或链错实现）。

## 9. 不变量（改代码前先读）

1. **`WouldBlock` ≠ EOF**：取不到数据返回"稍后再来"，由 Gate 决定静音；
   绝不让解码器看到假 EOF（否则整首歌会永久卡死）。
2. **窗口"到底"是一个位置**（`end_at: Option<u64>`），不是一个布尔。
3. **`cache.dat` 是环形覆盖**：正常播放期间不删缓存文件，不为"播过几首"清理。
4. **测速看累计下载字节**（`fetched_total`），不能看"窗口里剩多少"
   ——解码器同时在消费，稳态增量≈0，会永远误判成 `Starving`。
5. **一次播放 = 一个 `OPEN_TOKEN`**；seek 有自己的代数（语义不同，别合并）；
   预取只读播放代数，旧回调一律丢弃。
6. **`yhttp_online()` 之前必须先 `yhttp_init()`**（真机上顺序反了会 PC=0 崩溃）。
7. **Vita2D 字体必须在原生层加载**，不要在 JS 层重新引入字体预热、PJFA 上传或
   页面级字符缓存；UI 只提交 `TEXT_RUN` 并等待原生绘制。
8. **`app.tsx` 保持单文件**；`app/pocket.json` 的 `id` 与 `entry`
   （`apps/yunyin/main.tsx`）不要乱改。
9. **不要开 `YUNYIN_CATCH_HANG`**：0.13 的看门狗会在单帧超 2 秒时打断 guest。
10. **随包字体只有一个入口**：`pack.py` 把 `fonts/<YUNYIN_FONT>/` 里的字体改名成
    `app0:/fonts/yunyin.pvf`，运行期只读它。不要另外塞 TTF 兜底 —— 那会重新引入第二套渲染。

## 10. 卡里的数据（`ux0:/data/yunyin/`）

| 路径 | 说明 | 能删吗 |
| --- | --- | --- |
| `music/` | 本地曲库（mp3 / m4a / ogg / oga / wav / flac / opus） | 否 |
| `list/*.json` | 在线清单快照（应用自动生成） | 可（会重新同步） |
| `store/` | `favorites`（收藏）/ `session`（登录会话） | 否（会丢收藏/登录） |
| `cache.dat` + `cache.idx` | 在线歌磁盘缓存（32 MB 环形） | 可 |
| `covers/` | 封面解码缓存 | 可 |
| `debug` | **建了才写** `yunyin.log` | 开关文件 |
| `netdbg` | 建了才记 HTTP 逐条轨迹 | 开关文件 |
| `cookie.txt` | 〔可选〕手填会话（模拟器/扫码走不通时的后门） | 可 |
| `playlist.json` | 〔可选〕自己写的在线歌单 | 可 |

应用**不起任何服务、不监听端口**；所有文件都在这一个文件夹里。
