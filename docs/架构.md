# YUNYIN 架构

> 读者：要改这个项目的人（包括三个月后的自己）。
> 目标：一眼看清"东西在哪、数据怎么流、哪些规矩不能破"。
> 排障/构建命令见 [排障.md](排障.md)。

## 0. 一张图

```text
        ┌────────────────────────────── app/ （SolidJS 界面，PocketJS 0.13 宿主）──────────────────────────────┐
        │  app.tsx（唯一入口，帧循环 + 状态机）   core/*（音频口/曲库/主题/字库/性能）   pages/*   components/*  │
        └───────────────────────────────────────────┬──────────────────────────────────────────────────────────┘
                                          globalThis.api / globalThis.ui（FFI 桥）
        ┌───────────────────────────────────────────┴────────────────────── native/（Rust + C）───────────────────┐
        │  bridge.rs  ←→  media/{library,audio,lyrics,tags}  ←→  bgm.rs（音频线程 + BGM 口）                     │
        │  media/provider/netease/*（登录/歌单/榜单/URL 解析）        media/source/*（取数 + 缓存 + 缓冲策略）    │
        └───────┬──────────────────────────────────────────────┬──────────────────────────────────┬──────────────┘
                │                                              │                                  │
        net/yhttp.c（SceHttp/SceSsl，Range + 中止）      source/cache.dat（32 MB 环形磁盘缓存）   audio/yplayer.c（mpg123/vorbis/opus/wav）
```

数据只有两条来路：**卡里的本地曲库**（`ux0:/data/yunyin/music/`）和
**网易云在线**（清单 JSON + 加密接口 + Range 流）。界面只认"统一的曲目结构"，
不关心这首歌从哪来。

## 1. 目录 / 模块地图

| 路径 | 干什么 | 关键文件 |
| --- | --- | --- |
| `app/` | 界面层（PocketJS 应用目录，**目录名/结构由框架约定**） | `app.tsx`（唯一入口）、`pocket.json`、`colors.json` |
| `app/core/` | 与界面无关的"能力"：音频口、曲库、主题、字体入口、性能计时 | `audio.ts` `library.ts` `theme.ts` `cjk.tsx` `perf.ts` `motion.ts` |
| `app/pages/` | 右侧四个页签 + 子页 | `tracks.tsx` `albums.tsx` `menu.tsx` `settings.tsx` `lyrics.tsx` `account.tsx` |
| `app/components/` | 可复用控件 | `player.tsx`（左侧播放器卡片）`rows.tsx` `tabbar.tsx` `subpage.tsx` `focus_indicator.tsx` |
| `native/rs/` | 原生层主体（Rust） | `mod.rs` `bridge.rs` `bgm.rs` `media/…` |
| `native/audio/` | 解码与输出（C） | `yplayer.c`（mpg123/vorbis/opus/dr_wav）、`ym4a.c`、`yaac.c`、`yp_io_file.c` |
| `native/net/` | 网络（C，直接对 SceHttp/SceSsl） | `yhttp.c` |
| `native/host/` | 宿主侧小工具（C） | `yunyin_image.c`（封面解码）`yunyin_listdir.c`（目录扫描） |
| `native/vendor/`、`native/libs/` | 第三方单头库与预编译静态库 | `dr_wav.h` 等 |
| `asset/` | 主题素材（构建时复制成 app 内的 `asset/`） | `asset/ui/<主题>/*.png` |
| `fonts/` | Vita2D 原生字体 | `chinese/`、`japanese/` |
| `scripts/` | 构建与检查 | `build-vpk.py`（唯一打包入口）、`yunyin_build/`（实现）、`typecheck-app.sh` |
| `scripts/tools/` | 素材/曲库维护工具（不参与构建） | `gen-flat-themes.py` `gen-theme-icons.py` `tagcheck.py` |
| `tests/` | 宿主侧测试（cargo，不需要 Vita） | `cargo test` → 加密向量 / JSON / 环形缓存 / 缓冲策略 |

构建派生物（不入库，构建时自动生成）：
`app/theme-seed.tsx`（由 `colors.json` 生成）、`app/images.json`（扫 `asset/**` 生成）、
字体资源只以 `app0:/fonts/yunyin.pvf` 形式进入 VPK。

## 2. 界面层（app/）

* **`app.tsx` 是唯一入口、也是唯一的状态机**，故意保持单文件（官方 Playground
  预览要求同构）。它负责：帧循环、页签/子页切换、列表虚拟化、按键路由、状态词。
* **`core/` 里都是"能力"**，不认识界面：`audio.ts` 是对原生的薄封装，
  `library.ts` 管曲库与收藏，`theme.ts` 管 5 套配色（`colors.json` 是数据源，
  浅蓝/浅绿/浅紫由 `scripts/tools/gen-flat-themes.py` 从浅色派生），
  `cjk.tsx` 仅保留统一文本组件，实际字体由 Vita2D 原生层绘制，
  `perf.ts` 记账（`perf: JS 帧 …`）。
* **`pages/` 只画自己那一页**，`components/` 只画控件；两者都不直接碰原生，
  一律通过 `app.tsx` 传下来的访问器。
* 列表是**虚拟列表**：屏幕上只有 8~15 个 Item 节点，滚动复用；清单里的歌曲
  按需物化（只对可见窗口 + 邻窗解析），不做整表。

## 3. 原生层（native/rs/）

| 模块 | 职责 | 要点 |
| --- | --- | --- |
| `bridge.rs` | JS ↔ Rust 的 FFI 表（`globalThis.api`） | 所有同步入口都在这里，参数校验也在这里 |
| `bgm.rs` | 播放会话、音频线程、BGM 口、息屏续播 | 播放句柄只在音频线程换，换之前先 `join` |
| `media/library*` | 曲库扫描、收藏、歌词、标签 | 只读文件头 1 MB + 64 KB 元数据前缀 |
| `media/provider/netease/` | 登录（二维码）/ 歌单 / 榜单 / 每日推荐 / URL 解析 | `crypto.rs` 是 weapi/eapi 加密；`quality` 决定音质档 |
| `media/source/` | 在线播放的取数、缓存、缓冲策略 | 见下一节 |
| `platform/` | 卡里的路径、日志、store（键值文件）、时钟 | 日志/探针受卡里的开关文件控制 |

## 4. 在线播放链路（最要紧的一节）

```text
   resolve（加密接口拿 URL）
        ↓
   net/yhttp.c          一个 Range 请求 = 1 MiB（YHTTP_WINDOW）
        ↓
   source/http.rs       HttpRangeSource：**滚动预读队列**
                        · 块 1 MiB（与 C 侧窗口同尺寸）
                        · 预算 = 整首的 1/3，夹在 2–6 MiB（policy::readahead_budget）
                        · 取数线程抓满一块立刻抓下一块（不再"抓完就睡"）
                        · 升格换下来的块留两块复用（稳态零 malloc）
        ↓
   source/remote.rs     秒级 Gate（policy::GateState，纯逻辑、宿主可测）
        ↓
   audio/yplayer.c      解码 → PCM → BGM 口
```

**缓冲阈值（`source/policy.rs`，单位是"秒"不是 KB）**：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `START_BUFFER_MS` | 10 s | 首次启动要凑够才出声 |
| `MIN_BUFFER_MS` | 5 s | 播放中掉到它以下才 rebuffer（迟滞） |
| `RESUME_BUFFER_MS` | 8 s | rebuffer 后回到它才继续 |
| `TARGET_BUFFER_MS` | 20 s | 网络好时希望维持的量（预取让路判据） |
| `PREFETCH_MIN_BUFFER_MS` | 40 s | 下一首真正开跑要求的缓冲 |
| `PREFETCH_QUIET_MS` | 3 s | 用户刚按过键这段时间内**不预取**（保按键响应） |

**磁盘缓存（`source/diskcache.rs`）**：固定 32 MB 的 `cache.dat` + `cache.idx`，
环形覆盖、正常播放期间**不删文件**（SD2Vita 上最贵的是 create/write/close/remove）。
整首写满才登记进索引；正在播的那首被保护，写入会让开。

**TLS 与根证书**：`sceHttpsEnableOption(0x3D)` 打开进程级校验（服务器校验 / CN /
有效期 / 已知 CA），证书链交给 SceSsl。SceSsl 默认只认**固件自带**的根证书库，
而那个库跟着系统版本走 —— 所以 `certs/` 里随包带了一张 **DigiCert Global Root G2**
（网易云 API 与 `*.music.126.net` CDN 整条链都用它），`yhttp_init()` 里调
`yhttp_load_ca()` 用 `sceHttpsLoadCert` **额外注册**（不是替换固件库）：
成功 = 多一条可信根，失败（Vita3K 里该 API 未实现 / 真机历史上报 OOM）只记日志，
继续用固件库。

**下一首预取（`source/prefetch.rs`）**：只在"当前曲已全部到手"或
"缓冲 ≥ 40 s 且网络 FAST 且用户 3 秒没按键"时跑；单曲 > 16 MiB 不预取。

## 5. 在线清单：JSON 落盘 → 界面读文件

原生每次启动在后台把清单写成 JSON（`ux0:/data/yunyin/list/`），界面直接读文件，
**断网也能看上次的内容**：

| 文件 | 内容 | 来源 |
| --- | --- | --- |
| `discover.json` | 发现页：热门推荐歌单列表 | `/personalized` |
| `daily.json` | 每日推荐（需登录） | `/recommend/songs`（加密 weapi v3） |
| `account_playlists.json` | 我的歌单（需登录） | `/user/playlist` |
| `toplist_<榜单id>.json` | 四个榜单各一个文件 | `/playlist/detail` |
| `playlist_<歌单id>.json` | 打开过的歌单/榜单快照 | `/playlist/detail` |

写入用 **tmp + rename 原子替换**（掉电/强杀不会留半截 JSON）。
界面刷新是**事件驱动**：原生写完一个文件就记名（`listTouched`），界面只读变过的
那个文件（以前每帧 `stat` 全部文件，真机一次 35~86 ms）；另有 15 秒慢扫兜底。
一次更新里多份文件同时到达时，每 15 帧才应用一条，避免一帧解析几百 KB。

## 6. 字体渲染

* UI 文本统一产生 `TEXT_RUN`，由 Vita 宿主的 `native_text` 调用 Vita2D
  `vita2d_load_custom_pvf`；加载失败会明确记录 `mode=disabled`，不再回退到另一套字体实现。
* 运行时不再上传/刷新 PocketJS 的 PJFA 字体图集，也不再执行页面级预热、CJK
  stream、字体 LRU 或旧 `GLYPH_RUN` 绘制。文本提交量通过 `native-font:` 日志统计。
* 构建脚本只向 VPK 写入 `app0:/fonts/yunyin.pvf`。

## 7. 线程与性能纪律

| 规则 | 为什么 |
| --- | --- |
| 网络/磁盘 I/O 只在取数线程里做，**音频线程绝不等 I/O** | SD2Vita 抖动不能变成断音 |
| 帧循环里不做重活（解析大 JSON、重建绘制列表、每帧 stat 文件） | 真机上这些都是"卡一下"的来源 |
| 画面没变化就跳过 render/present（`frame_skip`） | 暂停/待机时省电、省发热 |
| 持续动画用**编译期烘好的 keyframe**（`animate-pulse` 等），一次性动画用 `animate()` | 稳态零 JS；官方只把 bake 用于固定循环 |
| 用户按键后 3 秒内不做后台预取 | 按键响应优先于"先把下一首下好" |

## 8. 构建流水线（`scripts/build-vpk.py`）

```text
pack.stage()            app/ + asset/ + native/ 暂存进 PocketJS 检出（apps/yunyin、hosts/vita）
apply_host_patches()    把官方宿主打成 YUNYIN 宿主（媒体模块、帧循环、正式包开关、诊断）
fonts.harvest_chars()      仅收集构建期字体覆盖信息，不生成运行时 PJFA 归档
pack.build_vpk()        bun tools/build.ts + tools/vita.ts（PocketJS 编译 + Rust/C 构建）
pack.repack()           换 TITLE_ID / 权限 eboot / 中文标题，重打 VPK → dist/
```

正式配置：`POCKETJS_ROOT=/root/pocketjs013 YUNYIN_BARE_GRAPHICS=1`。
`YUNYIN_BARE_GRAPHICS=1` 跳过与 0.13 渲染模型冲突的两组图形补丁（**正式包必须带**）。

## 9. 不变量（改代码前先读）

1. **`WouldBlock` ≠ EOF**：取不到数据返回"稍后再来"，由 Gate 决定静音；
   绝不让解码器看到假 EOF（否则整首歌会永久卡死）。
2. **窗口"到底"是一个位置**（`end_at: Option<u64>`），不是一个布尔。
3. **`cache.dat` 是环形覆盖**：正常播放期间不删缓存文件，不为"播过几首"清理。
4. **测速看累计下载字节**（`fetched_total`），不能看"窗口里剩多少"
   ——解码器同时在消费，稳态增量≈0，会永远误判成 `Starving`。
5. **一次播放 = 一个 `OPEN_TOKEN`**；seek 有自己的代数（语义不同，别合并）；
   预取只读播放代数，旧回调一律丢弃。
6. **`yhttp_online()` 之前必须先 `yhttp_init()`**（真机上顺序反了会 PC=0 崩溃）。
7. **Vita2D 字体必须在原生层加载**，不要在 JS 层重新引入字体预热、PJFA 上传或
   页面级字符缓存；UI 只提交 `TEXT_RUN` 并等待原生绘制。
8. **`app.tsx` 保持单文件**，`app/pocket.json` 的 id / 入口不要乱改。
9. **不要开 `YUNYIN_CATCH_HANG`**：0.13 的看门狗会在单帧超 2 秒时打断 guest。

## 10. 卡里的数据（`ux0:/data/yunyin/`）

| 路径 | 说明 | 能删吗 |
| --- | --- | --- |
| `music/` | 本地曲库（mp3 / m4a / ogg / wav / flac / opus） | 否 |
| `list/*.json` | 在线清单快照（应用自动生成） | 可（会重新同步） |
| `store/` | `favorites`（收藏）/ `cjkMode`（字库模式）/ `session`（登录会话） | 否（会丢收藏/登录） |
| `cache.dat` + `cache.idx` | 在线歌磁盘缓存（32 MB 环形） | 可 |
| `covers/` | 封面解码缓存 | 可 |
| `debug` | **建了才写** `yunyin.log` | 开关文件 |
| `netdbg` | 建了才记 HTTP 逐条轨迹 | 开关文件 |
| `cookie.txt` | 〔可选〕手填会话（模拟器/扫码走不通时的后门） | 可 |
| `playlist.json` | 〔可选〕自己写的在线歌单 | 可 |

应用**不起任何服务、不监听端口**；所有文件都在这一个文件夹里。
